# Специфікація діаграм послідовності

## 1. Загальний опис

У цій роботі розглядається варіант використання UC-03 «Додати гру до бібліотеки», який був обраний у попередній лабораторній роботі.

Метою є деталізація взаємодії між користувачем та внутрішніми компонентами системи під час виконання різних сценаріїв додавання гри до особистої бібліотеки.

## 2. Обраний варіант використання

**UC-03 — Додати гру до бібліотеки**

**Основний актор:** Авторизований користувач.

**Мета:** Додати вибрану відеогру до особистої бібліотеки користувача.

**Передумови:**
- Користувач має зареєстрований обліковий запис.
- Користувач увійшов у систему.
- Вибрана гра існує в каталозі.

**Результат:** Вибрана гра з'являється в особистій бібліотеці користувача.

## 3. Сценарії використання

Для побудови діаграм розглядаються три сценарії з попередньої лабораторної роботи.

### 3.1. Успішне додавання гри

- Користувач увійшов у систему.
- Гра існує в каталозі.
- Гра ще не додана до його бібліотеки.
- Користувач додає гру до бібліотеки.
- Система додає гру до особистої бібліотеки.
- Система відображає результат користувачу.

### 3.2. Повторне додавання гри

- Користувач увійшов у систему.
- Гра вже є в його бібліотеці.
- Користувач повторно додає цю гру.
- Система перевіряє наявність гри в бібліотеці.
- Система повідомляє, що гра вже знаходиться в бібліотеці.
- Повторний запис не створюється.

### 3.3. Спроба гостя додати гру

- Користувач не увійшов у систему.
- Гра існує в каталозі.
- Користувач намагається додати гру до бібліотеки.
- Система перевіряє авторизацію.
- Система відхиляє запит.
- Гра не додається до бібліотеки.

## 4. Учасники взаємодії

Для побудови діаграм послідовності визначено такі учасники:

| Учасник | Призначення |
|---|---|
| Авторизований користувач | Виконує додавання гри до бібліотеки |
| Гість | Намагається додати гру без авторизації |
| Інтерфейс користувача | Приймає дії користувача та відображає результати |
| AuthService | Перевіряє стан авторизації користувача |
| LibraryService | Виконує основну логіку роботи з бібліотекою |
| GameRepository | Отримує інформацію про гру з бази даних |
| LibraryRepository | Перевіряє та змінює вміст особистої бібліотеки |

### 4.1. Послідовність дій для успішного додавання гри

1. Авторизований користувач натискає кнопку додавання гри.
2. Інтерфейс передає запит до LibraryService.
3. LibraryService перевіряє авторизацію через AuthService.
4. GameRepository перевіряє наявність гри в каталозі.
5. LibraryRepository перевіряє, чи є гра в особистій бібліотеці.
6. Якщо гри ще немає, LibraryService додає її до бібліотеки.
7. Інтерфейс повідомляє користувача про успішне додавання.

### 4.2. Послідовність дій для повторного додавання гри

1. Авторизований користувач повторно натискає кнопку додавання гри.
2. Інтерфейс передає запит до LibraryService.
3. LibraryService перевіряє авторизацію через AuthService.
4. LibraryRepository перевіряє наявність гри в бібліотеці.
5. Система виявляє, що гра вже додана.
6. Новий запис не створюється.
7. Інтерфейс повідомляє користувача, що гра вже є в бібліотеці.

### 4.3. Послідовність дій для спроби гостя додати гру

1. Гість натискає кнопку додавання гри.
2. Інтерфейс передає запит до LibraryService.
3. LibraryService звертається до AuthService для перевірки авторизації.
4. AuthService визначає, що користувач не авторизований.
5. LibraryService відхиляє запит.
6. Інтерфейс повідомляє про необхідність увійти в систему.
7. Гра не додається до бібліотеки.
